## Decisions made
- Followed Task 4 exact contract: server-provided hidden list is authoritative; absent list defaults unnamed sources hidden, explicit [] shows everything. No `+sourceId` encoding (not supported by server). Master is excluded even if an invalid hidden list includes it.
- Server bus ordering is preserved; no client-side identity-based reordering or second permission model. X32 members can reach the mix page with zero buses to see the required message.
- Existing Ableton horizontal gesture remains intact; new vertical gesture uses exported axisLock after >10 px, with native `pan-x` scrolling and capture only after vertical classification.
- Client queue coalesces per bus/source at 50 ms; lock/page/connection/full-state changes cancel gestures, holds and queued sends. Existing `createFaderHolds` protects commits against echoes until echo/timeout.
- Admin shows linked canonical checkboxes, immediate toMain warnings and server warning on save. Hidden lists load lazily per member with bus selector; checked sources mean hidden. Save members before editing a newly assigned bus. With restrictions off, offer all visible buses for that member's hidden lists (server permission widening belongs to 0016).
- Hide/show requires a named identity because the API requires a member to save a personal list. Admin can edit another member's list through admin controls.
- Added an invisible master footer so master/source fader travel aligns.
