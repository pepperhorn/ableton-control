# X32 in-ear mixes, upcoming scenes and personal links — Implementation Plan

> **For agentic workers:** each task is dispatched to an implementer in its own worktree (ph-orch, AGENTS.md). Steps use checkbox (`- [ ]`) syntax. TDD: write the failing test, see it fail, implement, see it pass, commit.

**Goal:** Musicians get one web app showing upcoming scenes and controlling their own X32 mix bus, opened from a personal link.

**Architecture:**
- A standalone X32 module (`lib/osc.js`, `lib/x32.js`) speaks OSC over UDP with Node `dgram`. A fake X32 drives the tests and `dev.js`.
- `lib/app.js` gains a mix source switch (X32 or Ableton returns), bus permissions and hidden lists, and pushes X32 state to phones over the existing SSE stream.
- The web UI gains:
  - a scene window, in large form on Monitor and as a slim bar on the mix page
  - an X32 strip mixer
  - name/identity changes: 24-hour cookie, Log out, personal links

**Tech Stack:** Max for Live device; Node for Max (Node 16+ built-ins only, no npm deps); ES-module browser JS; `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-19-x32-mixes-design.md` (approved 2026-11-20). Read it before your task. Where this plan and the spec disagree, the spec wins; stop and say so.

## Global Constraints
- Runtime code uses Node built-ins only and must run on Node 16+. Max `js` stays ES5. No npm dependencies.
- X32 traffic runs in Node only, never in Max `js`, and must not touch the LiveAPI per-tick budget (≤150 operations, 0005).
- Phones never talk to the X32. Only the server does.
- **The server writes only these to the desk:**
  - send levels into a mix bus (`/ch|auxin|fxrtn/NN/mix/MM/level`)
  - a mix bus master (`/bus/MM/mix/fader`)
  It never writes Main LR, matrices, DCAs, pan, mute, EQ, names or colours. It never pushes saved levels on connect.
- **Fail closed:** while the X32 is not `connected` with a fresh snapshot, every X32 fader is disabled and every write is refused (409).
- **Desk state is the source of truth.**
- **UI class names:** `scene-window`, `scene-bar`, `mix-strip`, `mix-strip-master`, `mix-strip-hidden`, `member-link`. The font is Poppins.
- **Verify:** `cd setlist-touch && PATH=/home/shaun/.nvm/versions/node/v22.22.1/bin:$PATH npm test`. If you change the device patch: `python3 device/build_device.py && git status --short` must leave the tree clean after commit.

## Review Focus
1. **The X32 drops mid-drag.** The fader disables at once. A release after the drop is not written, and no stale value is written after reconnecting. Covered in T4.
2. **Member with no bus, or a bus number the desk doesn't report.** The mix page says "No mix bus assigned" or "Bus N not available" and nothing throws. Covered in T4 and T5.
3. **Member assigned the even bus of a linked pair** (e.g. 6 when 5/6 are linked). It is treated as the pair, shown as bus 5, and writes go to bus 5. Covered in T1 and T4.
4. **Unnamed or blank desk names.** Fallback labels are `Ch 07`, `Aux 3`, `FX 2` and `Bus 5`. Unnamed sources start hidden, and the master is never hidden. Covered in T1 and T5.
5. **The identity cookie expires while a page is open.** The next API call or SSE reconnect returns `kind:'none'`, the name overlay reappears, and no mix write is accepted for the old member. Covered in T3.

### Task 1 (0015-t1): X32 OSC client and fake desk

**Files:**
- Create: `device/lib/osc.js`, `device/lib/x32.js`, `device/lib/fake-x32.js`
- Test: `test/osc.test.js`, `test/x32.test.js`

**Interfaces — Produces:**
- `osc.encode(address: string, args: Array<number|string|{type:'i'|'f'|'s', value}>) -> Buffer`
  - Plain JS numbers encode as `f`, unless wrapped as `{type:'i'}`. Strings encode as `s`. Strings are 4-byte padded, big-endian.
- `osc.decode(buf: Buffer) -> {address: string, args: Array<number|string>} | null`
  - Returns `null` on a malformed packet. It never throws.
- `createX32({socket, host = null, discover = true, port = 10023, setTimer = setTimeout, clearTimer = clearTimeout, now = Date.now}) -> X32` (an EventEmitter). `socket` is a `dgram` socket or a test double with `send(buf, port, host)`, `on('message', fn)` and `setBroadcast()`.
  - `start()`, `stop()`
  - `setHost(ip: string | null)`: a manual IP wins over discovery. `null` returns to discovery.
  - `status() -> {state: 'searching'|'connected'|'lost', host: string|null, name: string, model: string}`
  - `snapshot() -> null | {buses: Bus[], sources: Source[]}`
    - `null` until the first full load completes.
    - `Bus = {bus: 1..16, name, color: 0..15, linked: boolean, toMain: boolean, master: number, sends: {[sourceId]: number}}`
      - For a linked pair, only the odd bus appears, with `linked: true`.
    - `Source = {id: 'ch/01'..'ch/32' | 'auxin/01'..'auxin/08' | 'fxrtn/01'..'fxrtn/08', kind: 'ch'|'auxin'|'fxrtn', number, name, color}`
    - Levels are the desk's 0..1 fader values.
  - `busFor(n: number) -> number | null`: maps an even bus of a linked pair to its odd partner. Returns `null` if the bus is out of range.
  - `setSend(bus, sourceId, value) -> boolean` and `setBusMaster(bus, value) -> boolean`
    - Both return `false` and send nothing unless `state === 'connected'` and the snapshot is loaded.
    - They clamp `value` to 0..1 and apply `busFor`.
  - Events:
    - `'status'` with `status()`
    - `'snapshot'` with `snapshot()` after each full load
    - `'level'` with `{bus, source: sourceId|'master', value}`
    - `'meta'` with `{target: sourceId|'bus/MM', name, color}`
- `levelToDb(value: number) -> string`: the X32 fader law below, formatted `-6.0 dB`. 0 gives `-inf dB`.
- `defaultLabel(target) -> string`: `Ch 07`, `Aux 3`, `FX 2`, `Bus 5`.
- `createFakeX32({buses, sources, linked, toMain}) -> {handle(buf, reply), state, writes: Array<{address, value}>}`
  - Answers the same OSC queries as a desk. Used by tests and by `dev.js` in T4.

**Desk protocol (from the unofficial Maillot X32/M32 OSC Remote Protocol; list each as a desk check in your return handoff):**
- Discovery and identity: send `/xinfo` to UDP 10023, broadcast, or the manual host. The reply args are `ip, name, model, version`.
- Keep-alive: `/xremote` every 8 s. Updates for changes made elsewhere arrive while it's renewed.
  - **`lost` (my value):** no reply to `/xinfo` within 3 s, or no packet at all for 20 s while connected.
  - Reconnect retries every 3 s.
- Read on connect, then emit `'snapshot'`:
  - `/ch/NN/config/name`, `/ch/NN/config/color`, and the same for `auxin` and `fxrtn`
  - `/bus/MM/config/name` and `/bus/MM/config/color`
  - `/config/buslink/1-2` … `/config/buslink/15-16`
  - `/bus/MM/mix/st` (`toMain`)
  - `/bus/MM/mix/fader`
  - `/<src>/NN/mix/MM/level` for every source and every bus that isn't the even half of a link
  - Pace the queries so they never exceed 200 in flight. The pacing scheme is the builder's call.
- **Fader law (`levelToDb`):**
  - `v >= 0.5` → `v*40 - 30`
  - `v >= 0.25` → `v*80 - 50`
  - `v >= 0.0625` → `v*160 - 70`
  - otherwise `v*480 - 90`
  - `v == 0` → `-inf`

### Task 3 (0015-t3): Identity, personal links, optional password (after T2 merges)

**Files:**
- Modify: `device/lib/access.js`, `device/lib/auth.js`, `device/lib/app.js`, `device/lib/config.js`, `device/web/js/access-view.js`, `access-render.js`, `app.js`, `device/web/index.html`
- Test: `test/access.test.js`, `test/auth.test.js`, `test/app.test.js`, `test/access-view.test.mjs`

**Interfaces — Produces:**
- **Member cookie:**
  - The payload becomes `{kind:'member', memberId, exp}`, with `exp = now + 24h`. `identify` rejects a payload where `exp` is missing or past.
  - `Max-Age=86400`.
  - The admin cookie is unchanged.
- **Separate identity cookie:**
  - `st_who` (signed, HttpOnly, 24 h) carries the member identity for display when `st_id` is an admin session.
  - `identify` returns `{kind:'admin', member?}` or `{kind:'open', member?}`, where `member` comes from `st_who` or the member payload.
  - Permissions are unchanged: admin and open stay full.
- `slugFor(name) -> string`:
  - Lowercase, with runs of non `[a-z0-9]` turned into `-` and trimmed.
  - `reservedSlug(slug)` is true for `'' , admin, api, js, css, fonts, settings, diagnostic, touch-test` and every existing top-level static path.
  - Member saves are refused with 400 `That name can't be used for a link` when the slug is empty, collides with a reserved path, or collides with another member's slug.
- **`GET /<slug>`:**
  - For a member slug, set the identity cookie (`st_id` member, or `st_who` when the request carries an admin session), then 302 to `/`.
  - An unknown slug serves the normal page.
- **`/api/me`:** adds `name` for admin and open when `member` is set, and `link` (the path `/<slug>`). `/api/members` (admin) adds `link` per member.
- **`allowOpenLan` setting:** boolean, default `false`. Editable in admin settings on loopback only.
  - When `password` is blank and `allowOpenLan` is true, auth returns `allowed` for LAN clients instead of `forbidden`.
  - Otherwise the existing behaviour is unchanged.
- **UI:**
  - The name overlay shows whenever `me` has no name and access is on. With access off, it is offered once, dismissible.
  - The header shows the name with a "Log out" button, which calls `POST /api/forget` (clears `st_id` member and `st_who`) and reloads.
  - Admin lists each member's full link (`http://<panel address>/<slug>`) with a copy button. Use `navigator.clipboard` where available, otherwise select the text.

### Task 4 (0015-t4): X32 in the server (after T1 and T3 merge)

**Files:**
- Modify: `device/lib/app.js`, `device/lib/access.js`, `device/lib/config.js`, `device/setlist-server.js` (create the `dgram` socket and X32 and pass them in), `device/dev.js` (fake X32 with `SETLIST_TOUCH_FAKE_X32=1`)
- Test: `test/app-x32.test.js`

**Interfaces — Consumes:** T1 `createX32`, `createFakeX32`, `busFor`, `levelToDb`. T3 `identify` with `member`.

**Interfaces — Produces:**
- **Config:**
  - `mixSource: 'x32'|'ableton'`. It defaults to `'ableton'` when any member has a non-empty `mixes`, otherwise `'x32'`.
  - `x32Host: string|null`
  - `members[].buses: number[]` (1..16, default `[]`)
  - `members[].hidden: {[bus]: string[]}` (sourceIds)
  - `validMembers` accepts these fields and stays valid for old configs.
- **Permissions:** `can(identity, 'busSend', bus)` is true for admin and open, or when the member's `buses` includes `busFor(bus)`.
- **`GET /api/x32`:** returns `{status, buses, sources, levels}`, filtered to buses the caller may control. The caller's own first bus comes first. Includes `hidden` for the caller's member, or for `?member=<id>` when admin. `levelToDb` labels are included.
- **`POST /api/x32-send {bus, source: 'master'|sourceId, value}`:**
  - 403 without permission.
  - 409 when not connected, or when `mixSource !== 'x32'`.
  - Coalesce to ≤ 20 writes/s per (bus, source), last value wins.
- **`PUT /api/x32-hidden {bus, hidden: string[], member?}`:**
  - A member edits only their own lists. Admin may pass `member`.
  - Validates sourceIds against the snapshot. `'master'` is never accepted.
- **`PUT /api/x32-settings {mixSource?, host?}`:** admin only. `host` is a dotted IPv4 or `null`, and it calls `x32.setHost`.
- **SSE events:**
  - `x32` carries the full filtered state for each client. Send it on connect, on snapshot, on meta and on status.
  - `x32level` carries `{bus, source, value, label}`. Throttle to ≤ 10/s per (bus, source) per client.
- **Admin warning:** assigning a bus with `toMain: true` returns `{warning: 'Bus 5 is routed to Main LR'}` but still saves.

**Interfaces — Produces:**
- `x32Strips(state, bus) -> Strip[]`
  - Strip order: the master first, then visible sources in desk order (`ch`, `auxin`, `fxrtn`, by number), then hidden ones in desk order.
  - Unnamed sources are hidden unless the member's list explicitly shows them. Store shown overrides as `'+' + sourceId` in the hidden list. *(Builder's call is fine if documented.)*
  - `Strip = {source, label, color, value, db, hidden, disabled}`
- `axisLock(dx, dy) -> 'x'|'y'|null`: decided once the movement passes 10 px. `'x'` when |dx| ≥ |dy|.

**Behaviour:**
- **Layout:**
  - One horizontal scrolling row. The master strip is `position: sticky; left: 0`.
  - Strips have vertical faders, the X32 colour (map 0..15 to the desk palette: off, red, green, yellow, blue, magenta, cyan, white, and their inverted variants) and dB text.
- **Hidden strips:** dimmed (`mix-strip-hidden`), at the end, with an inert fader. Tapping "Show" restores the strip.
- **Gestures:**
  - A sideways drag scrolls.
  - A vertical drag on a fader moves it, relative to where it was.
  - A tap never changes a level. Lock is respected.
  - Commit and echo hold use the existing `createFaderHolds`.
- **Disabled state:** shows "X32 not connected" or "Searching for X32…" over the row. Faders are disabled.
- **Tabs:** one per permitted bus, with the member's own bus first. Show "No mix bus assigned" when there are none.
- **Admin:**
  - mix source switch
  - X32 IP field with connection status
  - per member: bus checkboxes 1–16 (a linked pair shows as `5/6`), the toMain warning, and that member's hidden lists for each bus
- **Unchanged:** `scene-bar` from T2 stays on top with its toggle. The Ableton returns mode stays exactly as is.
